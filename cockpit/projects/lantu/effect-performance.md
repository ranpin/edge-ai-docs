## 1. 评测方法与工具

### 1.1 评测方式对比

| 评测方式           | 适用场景               | 优势说明                                                                                            |
| :----------------- | :--------------------- | :-------------------------------------------------------------------------------------------------- |
| **SDK 方式** | 算法快速验证阶段       | 便于直接读取本地 JSON 数据文件进行批量推理，快速验证模型效果与性能基线。                            |
| **APK 方式** | 完整业务链路与平台对接 | 集成 AADK 框架，通过 JNI 调用推理服务；与“元启”平台通过 HTTP 对接，便于自动化统计分析与云端评测。 |

### 1.2 日志提取命令

用于从运行日志中快速过滤出预处理耗时、推理耗时、最终结果等关键信息：

```bash
grep -E "image path:|PERF: ModelRunner::inference|final result|final reply|aadk.*: preprocess time" 0529-1741.log > 0529-1741grep.log
```

## 6. 后续待补数据与关注点

当前数据已覆盖效果 / 性能 / 系统监控主线，以下几项待后续补齐或持续关注：

- **功耗瓦数待补**：现有材料只有 CPU 占用%，无功率计实测瓦数（见 5.1 功耗模式行）
- **统一性能口径**：性能表需明确标注 Total 是基于几核模型（历史有单核 6559ms vs 3 核 3806ms 的差异），避免跨表数据打架
- **温度与性能关联**：建议并列「上海未加水冷」与「北京加水冷」数据——若单次推理温度差异不大、但连续推理后风冷组 TPS 下降而水冷组不降，即可证明水冷必要性
- **舱内效果待更新**：舱内指标取自 0817 报告（0828 仅测舱外），后续版本待补
- **评测自动化**：日志 grep 命令可封装成脚本（自动解析 log 输出 TTFT/TPS 均值方差），进一步提升评测效率

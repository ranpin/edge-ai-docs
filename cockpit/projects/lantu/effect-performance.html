一、 评测方法与工具

1. 评测方式对比

评测方式 适用场景 优势说明
SDK 方式 算法快速验证阶段 便于直接读取本地 JSON 数据文件进行批量推理，快速验证模型效果与性能基线。
APK 方式 完整业务链路与平台对接 集成 AADK 框架，通过 JNI 调用推理服务；与“元启”平台通过 HTTP 对接，便于自动化统计分析与云端评测。

六、 结合 2026-09-16 节点的复盘建议

将本部分与前一份《性能优化、存储与稳定性测试报告》合并后，整个项目的交付闭环已经非常清晰。针对后续数据填补，建议重点关注以下几点：

  1. 统一性能口径： 前一份报告中提到了“单核 6559 ms vs 3核 3806 ms”，在本报告的“性能指标统计表”中，务必明确标注当前填入的 Total 耗时是基于几核模型跑出的，避免数据打架。
  2. 量化“元启”平台的价值： APK 方式对接“元启”平台不仅是为了跑分，建议在汇报时补充一句：“通过元启平台实现了每日 CI/CD 自动化回归测试，将评测效率提升了 XX%”。这在 2026 年的大模型车规量产流程中是极具亮点的工程化能力。
  3. 温度与性能的关联分析： 在第五部分的“温度监控”表中，强烈建议将“上海未加水冷”和“北京加水冷”的数据并列填写。如果两者在单次推理下温度差异不大，但连续推理 10 次后水冷组的 TPS 没有下降而风冷组 TPS 下降，这就完美证明了水冷方案的必要性。
  4. 日志 grep 命令的规范化： 你提供的 grep 命令非常实用，但在正式文档中，建议将其封装成一个 Python 或 Shell 脚本（如 perf_analyzer.sh），自动解析 log 并输出上述表格中的 TTFT 和 TPS 均值/方差，进一步提升评测自动化程度。

## 2. 存储占用分析

### 2.1 排查命令工具

| 命令                      | 用途说明                                               |
| :------------------------ | :----------------------------------------------------- |
| `free -h`               | 查看系统整体内存占用信息（注：粒度较粗，不够准确）     |
| `dumpsys meminfo <pid>` | 查看指定进程的 CPU 侧内存占用详情                      |
| `dmabuf_dump <pid>`     | 查看指定进程的 DMA-BUF 占用（涉及 DSP/GPU/NPU 显存等） |

### 2.2 进程内存占用对比 (aiservice vs genai)

| 组成                                   | aiservice          | genai             | 差异                           |
| :------------------------------------- | :----------------- | :---------------- | :----------------------------- |
| **VmRSS (CPU 进程)**             | 4613 MB            | ~2030 MB          | ai 高 ~2.6 GB                  |
| **dma-buf (DSP, userspace_rss)** | 5888 MB            | 5501 MB           | 基本持平 (ai 高 ~0.4 GB)       |
| **合计 ≈ VmRSS + dma-buf**      | **~10.3 GB** | **~7.5 GB** | **ai 高 ~2.8 GB (~27%)** |

## 3. 稳定性测试

### 3.1 负载表现

- **高负载下**（stress 2核、16G）：CPU 占用率持续升高，呈阶段性稳定。
  - *初步猜测*：可能是由于内存高负载导致 CPU 频繁等待（I/O Wait 或内存换页），从而拉高了 CPU 占用率。
- **常规负载**（不设置 stress）：各项指标一切正常。

### 3.2 消融实验设计（阶梯形设置 stress）

为精准定位 CPU 占用升高的根因（是计算瓶颈还是内存带宽瓶颈），设计了以下阶梯式压力测试矩阵：

## 4. 关键结论与待关注点

### 4.1 已验证的关键结论

- **多核优化收益显著**：舱外问答全流程单核 `6559 ms` → 3 核 `3806 ms`，端到端时延降约 **42%**
- **水冷价值在持续高频场景**：09-02 台架 6h 连跑（8 场景 × 1334 次 = 10672 次推理）温度仅 36.96~38.34℃、TPS 全程稳定、未触发降频，证明水冷对防止 Thermal Throttling 有效；单次推理未触及温度墙（早期 3806ms 与上海未水冷一致），水冷价值体现在持续高频

### 4.2 待归因 / 待补全

- **存储占用差异待归因**：aiservice 比 genai 高约 2.8GB（VmRSS 多 2.6GB），需确认是多 LoRA 预加载 / AgentCore 框架开销 / Qwen3-Omni 上下文缓存，及有无压缩空间
- **消融实验待补全**：已完成「2 核 + 16G」与基线，剩余组（2 核 / 2 核+4G / 0 核+16G / 3-4 核+16G）待测，以定位 CPU 飙升是 Memory Bound 还是 Compute Bound

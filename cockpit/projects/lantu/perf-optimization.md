## 2. 存储占用分析

### 2.1 排查命令工具

| 命令                      | 用途说明                                               |
| :------------------------ | :----------------------------------------------------- |
| `free -h`               | 查看系统整体内存占用信息（注：粒度较粗，不够准确）     |
| `dumpsys meminfo <pid>` | 查看指定进程的 CPU 侧内存占用详情                      |
| `dmabuf_dump <pid>`     | 查看指定进程的 DMA-BUF 占用（涉及 DSP/GPU/NPU 显存等） |

### 2.2 进程内存占用对比 (aiservice vs genai)

| 组成                                   | aiservice          | genai             | 差异                           |
| :------------------------------------- | :----------------- | :---------------- | :----------------------------- |
| **VmRSS (CPU 进程)**             | 4613 MB            | ~2030 MB          | ai 高 ~2.6 GB                  |
| **dma-buf (DSP, userspace_rss)** | 5888 MB            | 5501 MB           | 基本持平 (ai 高 ~0.4 GB)       |
| **合计 ≈ VmRSS + dma-buf**      | **~10.3 GB** | **~7.5 GB** | **ai 高 ~2.8 GB (~27%)** |

## 3. 稳定性测试

### 3.1 负载表现

- **高负载下**（stress 2核、16G）：CPU 占用率持续升高，呈阶段性稳定。
  - *初步猜测*：可能是由于内存高负载导致 CPU 频繁等待（I/O Wait 或内存换页），从而拉高了 CPU 占用率。
- **常规负载**（不设置 stress）：各项指标一切正常。

## 4. 结合上一份总结的复盘建议（基于 2026-09-16 节点）

这份补充数据非常关键，直接回答了上一份总结中“缺少量化数据”的问题。为了将这两份文档完美融合，建议在最终汇报或简历中注意以下几点：

1. **突出多核优化的巨大收益**：
   在舱外问答全流程中，单核模型耗时 `6559 ms`，而3核模型降至 `3806 ms`，**端到端时延降低了约 42%**。这是一个极具说服力的工程优化成果，务必在总结中高亮。
2. **明确“水冷”的业务价值**：
   北京加水冷的**连续高频调用数据已补充**（见第一节 2.：2026-09-02 台架 6h 连跑、8 场景 × 1334 次 = 10672 次推理）。结果显示 6h 持续推理下温度仅 36.96~38.34℃、TPS 全程稳定、未触发降频，**直接证明了水冷对防止芯片降频（Thermal Throttling）的作用**。早期单次推理场景下舱外问答 3806ms 与上海未水冷一致，说明单次推理未触及温度墙——水冷的价值体现在持续高频场景。
3. **解释存储占用的差异**：
   `aiservice` 比 `genai` 高出约 2.8GB（主要是 VmRSS 多了 2.6GB）。在车机有限的内存资源下，需要解释这 2.6GB 是多 LoRA 预加载、AgentCore 框架开销，还是 Qwen3-omni 上下文缓存导致的？如果这是量产瓶颈，是否有进一步压缩的空间？
4. **完善消融实验结论**：
   目前的猜测“内存负载导致的cpu等待”非常专业。建议在完成表格中的剩余实验后，用一句话总结结论，例如：“经消融实验证实，CPU飙升主要由Memory Bound引起，而非Compute Bound，后续需优化内存换页策略或限制并发”。

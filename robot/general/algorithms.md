## 1. 机器人感知模型训练

### 1.1 数据飞轮

机器人感知系统的核心竞争力不在单次模型训练的精度，而在于**数据飞轮的转速**。一个高效运转的数据飞轮能够持续提升模型性能，自动发现和修复 corner case。

```mermaid
graph LR
    A["数据采集Collect"] --> B["数据标注Label"]
    B --> C["模型训练Train"]
    C --> D["端侧部署Deploy"]
    D --> E["线上监控Monitor"]
    E --> F["反馈回流Feedback"]
    F --> A
    E -->|"Hard Cases自动挖掘"| B
    F -->|"主动学习Active Learning"| B
```

### 1.2 Few-shot 学习与快速适配

机器人在新环境部署时，经常遇到训练集中不存在的物体。Few-shot 学习允许用少量样本（5-20 张图）快速适配新类别：

| 方法 | 样本需求 | 适配时间 | 精度 | 是否需端侧训练 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Metric Learning** | 5-10 shot | 即时推理 | 中等 | 否（特征比对） | 物体识别 |
| **Prompt Tuning** | 1-5 shot | 即时推理 | 中-高 | 否（文本引导） | 开放词汇检测 |
| **LoRA 微调** | 10-50 | 5-30 min | 高 | 可选 (边缘训练) | 精度敏感任务 |
| **域适应 (Domain Adaptation)** | 无标注 (目标域) | 1-4 hours | 中-高 | 通常云端 | 光照/场景迁移 |

> [!NOTE]
> **2025 的默认做法已被基础模型改写**：新物体适配的主流不再是「从头训分类器」，而是**冻结的基础特征 + 最近邻/线性探针**——用 DINOv2/v3、CLIP/SigLIP 类自监督或视觉-语言特征，把新物体的几张图编码进特征库，推理时做相似度比对；开放词汇检测（Grounding DINO / OWLv2 类）与视频分割（SAM 2 类）则承担「没见过的类别/实例」的零样本兜底。这类「特征库 + 检索」方案无需端侧训练、即插即用，是机器人感知 few-shot 适配的现实首选；LoRA 微调留给精度敏感、数据够多的场景。

### 1.3 Sim2Real 迁移策略

仿真数据几乎无限且标注免费，但"仿真-现实差距"（Sim2Real Gap）是落地的最大障碍。核心策略：

| 策略 | 原理 | 效果 | 代价 |
| :--- | :--- | :--- | :--- |
| **域随机化 (DR)** | 在仿真中随机化纹理、光照、物理参数 | 提高泛化性 | 仿真时间增加 2-5x |
| **域适应 (DA)** | 对抗训练对齐仿真/真实特征分布 | 减少分布偏移 | 需少量真实数据 |
| **渐进式迁移** | 仿真预训练 → 小规模真实微调 | 最优精度 | 需要真实标注数据 |
| **Photo-realistic Sim** | 使用高保真渲染器 (Isaac Sim, Habitat) | 缩小视觉差距 | GPU 资源消耗大 |
| **Real2Sim2Real（神经重建）** | 用 3DGS / NeRF 把真实场景重建为可交互仿真资产，再随机化 | 同时缩小视觉与布局差距 | 重建与资产编辑成本 |

> [!NOTE]
> **Sim2Real 的难度因任务类型天差地别**
>
> **足式/人形行走**的 Sim2Real 已相当成熟：接触模型相对简单、状态可精确测量、域随机化 + teacher-student 蒸馏基本够用（见 §5.4）。**接触密集的操作**（插拔、柔性物体、布料、流体）则是另一回事：接触力、形变、摩擦在仿真里极难精确建模，Sim2Real gap 至今未解决，这也是为什么操作类策略仍高度依赖**真机演示数据**（见 §4）而非纯仿真数据。做方案设计时，先判断任务落在哪一侧，再决定「仿真为主 + 随机化」还是「真机数据为主 + 仿真辅助」。

> [!TIP]
> **数据质量 > 数据数量**
>
> 在机器人感知领域，**500 张高质量标注 > 50000 张噪声标注**（经验法则）。高质量意味着：标注边界精确、覆盖多样场景、包含典型 hard case。建议投入 60% 的数据预算在质量控制上，而非单纯扩大数量。自动标注工具（如 SAM + CLIP 自动标注流水线）可以在保持质量的同时降低成本。

## 2. VLA 模型训练与适配

### 2.1 VLA 架构解析

Vision-Language-Action (VLA) 模型将视觉理解、语言理解和机器人动作生成统一到一个端到端框架中。核心思想是将机器人动作"token 化"（或用扩散/流匹配头直接生成连续动作），使大模型能够直接输出机器人控制指令。

```mermaid
graph LR
    subgraph 输入
        IMG["RGB 图像"]
        LANG["语言指令'拿起红色杯子'"]
    end

    subgraph Vision Encoder
        VE["ViT / SigLIP图像特征提取"]
    end

    subgraph Projection
        PROJ["线性投影层视觉 Token 对齐"]
    end

    subgraph Language Model
        LM["LLM Backbone(Llama / PaLM)"]
    end

    subgraph Action Head
        AD["离散路径De-tokenizer: Token → 连续动作"]
        DH["连续路径扩散 / 流匹配头: 直接生成动作块"]
    end

    subgraph 输出
        ACT["7-DoF 动作(dx,dy,dz,rx,ry,rz,gripper)"]
    end

    IMG --> VE --> PROJ --> LM
    LANG --> LM
    LM -->|"自回归吐 action token"| AD --> ACT
    LM -->|"潜特征条件"| DH --> ACT
```

> [!NOTE]
> **Action Tokenizer 在训练侧，不在推理主路径**
>
> 离散动作路线里，「连续动作 → 离散 token」的 **Action Tokenizer** 只在**训练/数据准备**阶段把演示动作转成 LM 的监督目标；**推理**时 LM 自回归吐出 token，再由 **De-tokenizer**（查 bin 中心 + 反归一化）还原为连续动作。把 tokenizer 画进推理前向链是常见误解。扩散/流匹配路线则没有显式 tokenizer，动作头直接输出连续动作块。

动作头有三种主流形态，直接决定推理频率与端侧可行性：

| 动作头形态 | 代表模型 | 生成方式 | 特点 |
| :--- | :--- | :--- | :--- |
| **离散 Action Token** | RT-1 / RT-2 / OpenVLA | 自回归逐 token 解码（每维约 256 bins） | 复用 LLM 词表与解码器，但多步解码慢 |
| **扩散头 (Diffusion)** | Octo / RDT-1B / GR00T N1/N1.5 | 迭代去噪生成动作块 | 多模态动作分布，去噪步数是延迟旋钮 |
| **流匹配 (Flow Matching)** | π0 / π0.5 | 少量积分步生成动作块 | 比 DDPM 去噪更快，适合 50Hz 级输出 |

> [!NOTE]
> **2025 年的两条「提速」改良**
>
> - **FAST 压缩动作 token（π0-FAST，2025）**：朴素离散化把每个动作维独立切 bin，token 序列长、自回归解码慢。FAST 先对动作块做 **DCT（频域变换）+ BPE 压缩**，把一段动作压成少量 token，使「自回归 VLA」的训练与推理效率大幅改善，重新变得可与扩散头竞争。
> - **并行连续解码（OpenVLA-OFT，2025）**：不再逐 token 自回归，而是一次前向**并行**输出整个动作块、用连续表示 + L1 回归（而非 256-bin 分类），配合 action chunking，把 7B 级 VLA 的控制频率显著拉高。说明「离散 token = 慢」并非宿命，解码方式才是关键变量。

> [!TIP]
> **扩散/流匹配头 vs 自回归 token：怎么选**
>
> 这是 VLA 设计里最核心的取舍之一，没有绝对赢家：
>
> | 维度 | 自回归离散 token | 扩散 / 流匹配头 |
> | :--- | :--- | :--- |
> | **与语言/推理共训** | 天然——动作就是「词」，可与文本、思维链交错训练（RT-2、π0-FAST 走这条） | 较难——动作专家与 LM 头解耦，语言推理与动作生成是两套目标 |
> | **动作精度** | 受 bin 量化限制（256 bin ≈ 有限分辨率） | 连续输出，精度高，适合灵巧/接触密集任务 |
> | **多模态动作** | 可表达（采样不同 token 序列） | 天然表达（去噪/积分到不同模态） |
> | **推理延迟** | 逐 token 解码，chunk 越长越慢（FAST/OFT 可缓解） | 整块并行生成，去噪/积分步数是延迟旋钮 |
> | **训练稳定性** | 成熟（next-token prediction） | 较敏感（去噪调度、步数、损失加权需调） |
>
> **2025-2026 的实际收敛**：强调**灵巧操作与高频控制**的强 VLA（π0/π0.5、GR00T N1/N1.5、RDT、Helix S1）普遍选扩散/流匹配头；强调**语言推理与跨任务共训**的路线（RT-2、Gemini Robotics、π0-FAST）保留自回归 token。端侧视角：扩散头的「步数旋钮」比自回归的「token 数旋钮」更容易在延迟预算内调优，这是双系统架构（§2.2）把高频动作交给扩散/流匹配小头的根本原因。

> 3. **端侧 VLA 出现「原生小模型」路线**：过去只能「云端大模型蒸馏下沉」，2025 起 SmolVLA、Gemini Robotics On-Device 直接面向嵌入式设计，端侧不再只是「压缩后的次品」。

### 2.3 边缘压缩 Pipeline

将云端 VLA 模型压缩到端侧可运行的规模，需要多阶段联合优化（下表**压缩率/精度损失为示例口径**，实际取决于模型、任务与量化方案，须按你的栈实测）：

| 阶段 | 技术 | 压缩率（示例） | 精度损失（示例） | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 1. 结构化剪枝 | 移除注意力头、FFN 通道 | 2-4x 参数减少 | 3-8% | 需要微调恢复精度 |
| 2. 知识蒸馏 | 大模型 Teacher → 小模型 Student | 5-10x 参数减少 | 2-5% | 学习中间表征效果更好 |
| 3. 量化 | INT8/INT4 权重量化 | 2-4x 内存减少 | 0.5-2% | PTQ 通常即可 |
| 4. 算子融合 | Attention + LayerNorm 融合 | 1.3-2x 速度提升 | 0% | 框架级优化 |

> [!WARNING]
> **VLA 压缩不能「一刀切」：骨干与动作头的量化容忍度不同**
>
> VLA 是「VLM 骨干 + 动作头」的复合体，两部分的压缩策略应分开：
>
> - **VLM 骨干**（占绝大多数参数）：可激进压缩——W4A16 权重量化、结构化剪枝、蒸馏，与端侧 LLM 同一套打法（见 [Embodied Agent 篇](embodied-agent.html)）。
> - **扩散/流匹配动作头**（参数少但直接决定动作精度）：对量化**更敏感**，低比特容易让去噪轨迹漂移、动作抖动；通常保留 FP16/INT8，并把「去噪步数」而非「位宽」当作首要延迟旋钮。
> - **视觉编码器**：可单独换轻量骨干（DINOv2/SigLIP → MobileNet 级）或离线预编码，是性价比最高的瘦身点。
>
> **另一条路：不压缩，直接选原生小模型**。2025 起 SmolVLA（~450M）、Gemini Robotics On-Device 面向嵌入式设计，省去「压缩 7B → 端侧」的精度博弈；OpenVLA-OFT 则证明「换解码方式」比「砍参数」更能救回控制频率。压缩 vs 原生小模型，是端侧 VLA 选型的第一道分叉。

> [!WARNING]
> **VLA 端侧部署的现实挑战**
>
> 小型 Transformer VLA（几十 M 级，如 Octo 93M）在 Orin 级平台上单帧推理通常在几十至上百 ms 量级（示例口径，需按你的模型与平台实测），勉强满足 5-10Hz 的控制频率要求；要达到 30Hz+ 实时灵巧操作，需进一步压缩模型或改用双系统分频架构。**Action Chunking**（一次预测多步动作）是当前最有效的缓解策略 —— 模型以 5Hz 重规划、每次输出未来 10 步动作，执行器在 chunk 间隔内以 50Hz 回放动作序列。注意：这只提高**执行平滑度**，反应性仍受 5Hz 重规划频率限制；配合 **temporal ensembling**（对重叠 chunk 的预测做指数加权平均）是 ACT 的标准做法，能同时改善平滑性与反应性。

## 3. 扩散策略与 ACT

### 3.1 与 VLA 并列的策略族

Diffusion Policy 与 ACT 是**不依赖大语言模型骨干**的模仿学习策略族：直接学习「观测 → 动作块」映射，通常不带语言输入（或以语言 embedding 为条件）。它们是理解 VLA 动作头的前置知识 —— π0 的流匹配头、Octo/RDT/GR00T N1 的扩散头，本质都是把这一族的技术装进了 VLA。

```mermaid
graph LR
    subgraph 观测
        O1["多视角 RGB"]
        O2["本体状态关节角/夹爪"]
    end

    subgraph 策略网络
        ENC["视觉编码器ResNet / ViT"]
        CORE["策略核心U-Net (Diffusion Policy)CVAE+Transformer (ACT)"]
    end

    subgraph 输出
        CHUNK["动作块 H 步未来动作序列"]
    end

    O1 --> ENC --> CORE
    O2 --> CORE
    CORE --> CHUNK
    CHUNK -->|"高频回放 + temporal ensembling"| EXEC["机器人执行"]
```

### 3.2 三种策略形态对比

| 策略形态 | 代表工作 | 动作生成方式 | 优点 | 局限 | 端侧友好度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **行为克隆 (BC)** | 经典 MLP/CNN 策略 | 单步回归 (MSE) | 最简单、推理最快 | 多模态动作被平均、误差累积 | 高 |
| **ACT** | ALOHA (Zhao et al.) | CVAE + Transformer，一次出动作块 | 双臂精细操作（穿线、开柜），动作块抑制误差累积 | 每任务需专门演示数据 | 高 |
| **Diffusion Policy** | Chi et al. | DDPM/DDIM 迭代去噪生成动作块 | 天然表达多模态动作分布、轨迹平滑 | 去噪迭代引入延迟，需减步数 | 中-高 |
| **VLA** | OpenVLA / π0 等 | 自回归 token / 扩散 / 流匹配 | 语言泛化、跨任务 | 模型大、频率低 | 中-低（压缩后） |

> [!NOTE]
> 「VLA 频率低」是 2024 的刻板印象，2025 已被部分打破：OpenVLA-OFT 的并行连续解码、π0-FAST 的压缩 token、SmolVLA 的原生小模型，都把 VLA 的控制频率拉到可用区间。扩散/流匹配头与自回归 token 的系统取舍见 §2.1。ACT / Diffusion Policy 这类**不带语言骨干**的策略族，仍是单任务端侧部署的默认选择——它们与 VLA 不是替代关系，而是「专用 vs 通用」「端侧 vs 云端」的分工。

### 3.3 端侧部署要点

- **去噪步数是延迟旋钮**：DDPM 原始需上百步，端侧用 DDIM 采样压到 5-10 步，或用一致性蒸馏（Consistency Distillation）做到 1-2 步；π0 选流匹配正是因为它天然少步数。
- **动作块长度 H 的权衡**：H 大 → 推理频率需求低但反应迟钝；H 小 → 反应快但推理压力大。典型 H 为 8-64 步（示例口径），配合 temporal ensembling 使用。
- **训练数据需求**：单任务通常 50-200 条高质量演示即可收敛（经验值），远小于 VLA 预训练需求 —— 这是「小模型 + 专用任务」路线在端侧仍占优的根本原因。

## 4. 遥操作与真机数据管线

### 4.1 为什么真机数据是具身智能的最大瓶颈

模仿学习类模型（ACT / Diffusion Policy / VLA 微调）的上限由**真机演示数据**决定：仿真数据有 Sim2Real gap，人类视频没有动作标签。遥操作（teleoperation）是用低成本方式采集「观测-动作」配对数据的标准手段，其质量与规模直接决定策略性能。

> [!IMPORTANT]
> **「数据是最大瓶颈」不是口号，是工程现实**
>
> - **采集成本以「人·分钟」计**：一条高质量遥操作轨迹要人全程盯着操作，单条几十秒到几分钟，还要剔除失败与抖动。和互联网图文/视频「免费海量」完全不同，真机动作数据是**逐条花钱攒出来的**。
> - **数据金字塔**：2025 的通用 VLA（GR00T N1、π0.5）都按「金字塔」配比数据——底层是**海量网络视频/人类第一视角视频**（量大、无动作标签，学常识与视觉先验），中层是**合成/仿真数据**（可无限生成、有动作标签但有 sim2real gap），顶层是**少量真机遥操作**（最贵、最准，决定最终可用性）。端侧专用策略则几乎全靠顶层。
> - **数据规模定律：多样性 > 条数**。2024-2025 的机器人数据 scaling 研究（如 imitation learning 数据规模律）发现：策略性能随演示数呈幂律提升，但**环境/物体/任务的多样性**比单纯堆同一场景的条数更能带来泛化——100 条来自 10 个场景，通常优于 1000 条来自 1 个场景。这直接决定了数据采集要「铺场景」而非「刷条数」。
> - **跨本体不是免费午餐**：把 A 机器人的数据拿去帮 B 机器人（cross-embodiment）能带来视觉/语义层面的迁移，但动作空间、夹爪、动力学不一致会造成**负迁移**；Open X-Embodiment 的价值主要在表征预训练，而非直接复用它人的动作轨迹。

### 4.2 主流遥操作方案

| 方案 | 代表系统 | 原理 | 成本 | 数据特点 |
| :--- | :--- | :--- | :--- | :--- |
| **主从同构臂** | ALOHA / Mobile ALOHA | 操作员拖动 leader 臂，follower 臂实时关节映射 | 中（两套同构臂） | 动作标签精确、可达 50Hz，双臂精细操作数据的事实标准 |
| **手持夹爪采集** | UMI | 手持 3D 打印夹爪 + GoPro 鱼眼相机，人直接在环境中采集，事后 SLAM 恢复位姿并 retarget 到机器人 | 低 | 摆脱机器人本体限制，可众包大规模采集；retarget 误差是主要噪声源 |
| **外骨骼映射** | GELLO | 低成本外骨骼式 leader 装置，关节一一对应 | 低 | 适合单臂操作，直觉性好 |
| **VR / 手柄遥操作** | Quest + 逆运动学 | 头显/手柄位姿 → IK 解算机械臂 | 低 | 位姿级控制，适合导航与粗操作，精细操作数据质量一般 |
| **人类视频学习** | Ego4D 类数据 | 第一视角视频 + 动作推断 | 极低（现成数据） | 无机器人动作标签，需动作重定向/推断，多用于预训练（如 GR00T N1） |

### 4.3 真机数据管线

```mermaid
graph LR
    A["遥操作采集ALOHA / UMI"] --> B["质量过滤失败/抖动轨迹剔除"]
    B --> C["动作对齐retarget + 时间戳同步"]
    C --> D["统一格式LeRobot dataset"]
    D --> E["训练/微调ACT / DP / VLA"]
    E --> F["端侧部署评估"]
    F -->|"失败案例回流"| A
```

关键工程点：

1. **统一数据格式**：HuggingFace **LeRobot** 已成为开源机器人数据的事实标准格式；跨本体大规模数据可参考 **Open X-Embodiment**（22 种机器人本体、百万级轨迹，RT-X / Octo / OpenVLA 的预训练底座）。2025 起出现**单一机构、单一人形/操作平台**的更大规模开源集，如 **AgiBot World（智元，2025，百万级真机轨迹、百台机器人、数百任务，具体数字需核实）**，把「真机数据」从实验室级推到工业级。
2. **动作对齐比数据量更关键**：遥操作记录的动作与机器人实际执行存在延迟与坐标系差异，时间戳错位会系统性污染策略（与传感器时间同步是同一类问题，见 [部署篇](deployment.html)）。
3. **数据规模经验值**：单任务 BC 约 50-200 条演示；跨任务泛化策略需要数万至百万级轨迹的混合数据集 —— 这正是「通用 VLA 是云端游戏、端侧做专用小策略」格局的数据侧原因。
4. **2025-2026 的「数据工厂」化**：人形厂商开始把数据采集当成**产线**而非实验——Figure 的 BotQ、Tesla 的数据引擎、国内智元/银河通用等的集中采集车间，用「多套遥操作工位并行 + 标准化任务脚本 + 自动质检」批量产出真机数据。配套趋势是**人类第一视角视频 retarget**（EgoMimic / Aria 类）与**世界模型合成数据**（见 §7）作为真机采集的补充，但二者都还替代不了顶层真机数据。

## 5. 强化学习与 Sim2Real

### 5.1 RL 训练流程总览

机器人强化学习的核心难点在于样本效率和安全性 —— 真实机器人不可能像游戏 AI 那样试错百万次。因此，"仿真训练 + Sim2Real 迁移" 成为标准范式。

```mermaid

    end
```

### 5.2 策略蒸馏：RL Teacher → SL Student

RL 策略通常是大型神经网络，且依赖仿真中的特权信息（如精确物体位姿）。策略蒸馏将其压缩为可在端侧运行的轻量模型，同时去除对特权信息的依赖：

```
# 策略蒸馏伪代码
# 1. 收集 Teacher 轨迹
teacher_policy = load_rl_policy("ppo_grasp_v3.pt")  # 大模型, 使用特权信息
trajectories = []
for episode in range(10000):
    obs_privileged = env.get_privileged_obs()  # 包含精确位姿
    obs_student = env.get_visual_obs()          # 仅 RGB 图像
    action = teacher_policy(obs_privileged)
    trajectories.append((obs_student, action))

# 2. 训练 Student (行为克隆)
student_policy = LightweightCNN(input="RGB", output="7DoF_action")
for obs, action in DataLoader(trajectories):
    pred_action = student_policy(obs)
    loss = F.mse_loss(pred_action, action)  # + 正则项
    loss.backward()
```

> [!WARNING]
> **两个蒸馏陷阱（足式之外的操作任务尤其明显）**
>
> 1. **离线 BC 的协变量偏移**：上面只在 teacher 自己走过的状态上采集数据，student 一旦偏离就会进入没见过的状态并滚雪球。标准解法是 **DAgger / 在线蒸馏**——让 student 自己 rollout、在 student 实际遇到的状态上请 teacher 打标签，迭代纠正。
> 2. **MSE 会「平均掉」多模态 teacher**：若 teacher 在同一观测下有多个合理动作（抓取可从左也可从右），MSE 回归会学出两者的**均值**（从中间撞上去）。足式步态 teacher 接近确定性、MSE 够用；操作类随机 teacher 应改用**扩散/流匹配 student**或按模态拆分，别直接 MSE。

### 5.3 域随机化技术

域随机化通过在仿真中引入大范围的环境变化，迫使策略学习不依赖特定视觉/物理特征的鲁棒行为（下表**典型范围为示例口径**，须按你的本体与仿真器标定）：

| 随机化类型 | 随机化参数 | 典型范围（示例） | 对 Sim2Real 的影响 |
| :--- | :--- | :--- | :--- |
| **视觉随机化** | 纹理、光照方向/强度、相机位姿、背景 | 纹理:随机图案, 光照:0.2-5x, 相机:±10cm/±5° | 消除视觉域偏差，最关键 |
| **动力学随机化** | 摩擦系数、物体质量、关节阻尼 | 摩擦:0.1-2.0, 质量:0.5-2x, 阻尼:0.8-1.2x | 适应真实物理参数不确定性 |
| **执行器/延迟随机化** | 电机延迟、力矩饱和、齿轮背隙、控制周期抖动 | 延迟:0-30ms, 力矩:±20% | 足式/人形真机不发散的关键（见 §5.4） |
| **物理随机化** | 重力方向微扰、仿真步长、接触刚度 | 重力:±5%, 步长:1-4ms | 提高对仿真器误差的鲁棒性 |
| **任务随机化** | 目标位置、初始构型、障碍物布局 | 全工作空间采样 | 提高泛化能力 |

> [!NOTE]
> **自动域随机化（ADR）**：手动调随机化范围很费劲——范围太小学不到鲁棒性，太大策略学不出来（过于保守）。ADR（OpenAI 2019 起）让随机化范围**随策略能力自动扩张**：策略在当前范围表现够好，就加大随机化幅度，形成课程。2025 的人形/灵巧手 RL 普遍采用 ADR 式自动课程，而非手填固定范围。

### 5.4 足式与人形步态 RL

四足/人形行走是当前 RL Sim2Real 最成功的落地场景，已形成标准范式：

```mermaid
graph LR
    A["GPU 大规模并行仿真Isaac Lab / MuJoCo MJX / Genesis数千环境同时 rollout"] --> B["PPO 训练特权 Teacher使用精确状态/地形信息"]
    B --> C["Teacher-Student 蒸馏Student 只用 IMU+关节编码器+高度图"]
    C --> D["真机部署端侧 MLP 推理（毫秒级，示例）@50Hz 步态频率"]
    D --> E["地形课程Curriculum平地→斜坡→楼梯→碎石"]
```

> [!NOTE]
> **仿真器口径（2025-2026）**：**Isaac Gym 已被 NVIDIA 弃用**，后继是构建在 Isaac Sim 上的 **Isaac Lab**；MuJoCo 侧用 **MJX**（JAX/GPU 并行）与 DeepMind 的 **MuJoCo Playground**（2025，RL 环境套件）；**Genesis**（2024 末）是新兴的高速生成式物理引擎。资料里若仍写「Isaac Gym」，按「Isaac Lab」理解。

关键要素：

- **奖励设计是调试大头**，典型项分三类：① **指令跟踪**（基座线速度 x/y、角速度 yaw 跟踪，是主奖励）；② **正则/平滑**（动作变化率、力矩、能耗、关节加速度惩罚，抑制抖动与发热）；③ **步态与安全**（足端离地时间、步频/相位、对称性、基座高度与姿态、接触力上限、防摔存活奖励）。奖励项权重需要大量调参，是 sim2real 成败的隐性关键。
- **随机化重点与操作任务不同**：足式更依赖**动力学随机化**（质量、摩擦、电机延迟、推力扰动），视觉随机化次之。
- **执行器建模是成败关键**：电机延迟、齿轮背隙、力矩饱和必须显式建模或随机化，否则真机步态发散。
- **端侧形态**：蒸馏后的 Student 策略通常只是几层 MLP，推理开销可忽略 —— 与 VLA 的算力困境形成鲜明对比，这也是「RL 管腿、VLA 管手」成为人形机器人常见分工的原因。
- **2025-2026 的延伸**：从「平地行走」走向 **exteroceptive locomotion**（用视觉/高度图过楼梯、碎石）、**whole-body / loco-manipulation**（边走边用手臂操作）、以及**真机 RL 微调**（在真实机器人上用少量交互继续训练，缓解纯仿真的残余 gap）。人形比四足更难：高重心、欠驱动、脚踝柔顺与接触建模误差被放大，摔倒代价高，安全约束与课程学习更重。

> [!CAUTION]
> **Sim2Real Gap 是第一大挑战**
>
> 即使使用了全面的域随机化，仿真中的高成功率在真实世界通常要打明显折扣（经验上 95% 仿真成功率对应真机 60-80%，示例口径）。差距主要来自：**接触物理建模不准确**（软物体、柔性物体）、**传感器噪声模型不完善**（深度相机在反光表面失效）、**执行器延迟和响应差异**。最有效的弥补方法是在真实环境中进行少量（50-200 episodes）的微调适应。

### 5.5 用 RL 给 VLA 做后训练（2025-2026 趋势）

纯模仿学习（BC / VLA 微调）有个硬上限：**策略不会超过演示者**，且对演示没覆盖的状态束手无策。2025 起出现一批「**先模仿预训练、再用 RL 后训练**」的工作，把 RL 的「试错改进」叠加到 VLA 的「泛化先验」上：

| 思路 | 做法 | 价值 | 难点 |
| :--- | :--- | :--- | :--- |
| **RL 微调预训练 VLA** | 以 VLA 为初始策略，用任务奖励（成功/失败、稀疏或过程奖励）做 PPO/GRPO 式更新 | 突破演示上限、提升成功率与鲁棒性 | 真机试错昂贵且有风险；奖励难设计；大模型 RL 训练不稳定 |
| **仿真 RL + 真机蒸馏** | 在仿真里用 RL 训 teacher，再蒸馏到 VLA/小策略 | 安全、可大规模并行 | 操作类 sim2real gap 仍在（见 §1.3） |
| **残差 RL（residual）** | VLA/BC 出基础动作，RL 只学一个小的「修正量」叠加 | 保留先验、改动小、更安全 | 残差空间设计、与基础策略的耦合 |
| **人类反馈/偏好（RLHF-lite）** | 用人类偏好或纠正信号在线更新 | 对齐用户意图、无需显式奖励 | 反馈稀疏、在线更新稳定性 |

> [!NOTE]
> **代表工作与口径**：2025 年 RL 后训练 VLA 是活跃研究方向（如 iRe-VLA、VLA-RL、ConRFT、SimpleVLA-RL 等，**具体名称/结论需核实**），但尚无「公认最佳配方」。面试或方案里稳妥的表述是：「模仿学习负责泛化先验与冷启动，RL 后训练负责突破演示上限」，并强调**真机 RL 的安全与样本效率仍是未解难题**——不要把「RL 微调 VLA」说成已成熟的标准流程。

## 6. 持续学习与在线适应

### 6.1 端侧增量学习

人形/具身机器人进入用户家中后，会不断遇到新物体和新场景。端侧增量学习允许机器人在不回传数据的情况下持续提升能力：

| 能力 | 技术方案 | 计算开销 | 内存开销 | 适用性 |
| :--- | :--- | :--- | :--- | :--- |
| 新物体识别 | 特征库扩展 + Nearest Neighbor | 极低（前向推理） | 每物体约 2KB（1024 维 fp16 特征，示例口径） | 所有平台 |
| 新场景适应 | Batch Norm 统计量更新 | 低（仅统计量） | 可忽略 | 所有平台 |
| 新技能学习 | LoRA 微调 + Replay Buffer | 中（需 GPU） | LoRA 约 1-5MB | Orin 级别 |
| 偏好学习 | 人类反馈 (RLHF-lite) | 中（在线更新） | 反馈缓冲区约 10MB | Orin 级别 |

### 6.2 灾难性遗忘缓解

增量学习的核心问题是**灾难性遗忘** —— 学习新任务时遗忘旧任务。三种主流缓解策略：

| 方法 | 原理 | 额外存储 | 计算开销 | 效果 |
| :--- | :--- | :--- | :--- | :--- |
| **EWC (Elastic Weight Consolidation)** | 用 Fisher 信息矩阵约束重要权重 | 与模型参数等大 | 中等 | 对简单任务序列有效 |
| **Experience Replay** | 保存旧任务小样本，混合训练 | Replay Buffer (50-500 样本) | 低 | 最实用、效果稳定 |
| **Progressive Networks** | 为新任务添加新列，通过横向连接复用旧知识 | 线性增长 | 推理时增加 | 无遗忘，但不可扩展 |

### 6.3 边缘联邦学习

多台机器人在不共享原始数据的前提下协同提升模型性能。这对进入家庭的人形机器人尤其重要 —— 用户隐私数据（家庭布局、个人物品）绝不能上传。

```mermaid
graph TB
    subgraph 机器人终端
        R1["人形 A家庭场景"]
        R2["人形 B办公场景"]
        R3["人形 C商场场景"]
    end

    subgraph 本地训练
        L1["本地微调LoRA ΔW_A"]
        L2["本地微调LoRA ΔW_B"]
        L3["本地微调LoRA ΔW_C"]
    end

    subgraph 聚合服务器
        AGG["FedAvg 聚合ΔW = avg(ΔW_A, ΔW_B, ΔW_C)"]
    end

    subgraph 全局模型
        GM["更新后全局模型W' = W + ΔW"]
    end

    R1 --> L1 -->|"上传梯度/LoRA"| AGG
    R2 --> L2 -->|"上传梯度/LoRA"| AGG
    R3 --> L3 -->|"上传梯度/LoRA"| AGG
    AGG --> GM
    GM -->|"下发更新"| R1
    GM -->|"下发更新"| R2
    GM -->|"下发更新"| R3
```

> [!NOTE]
> **隐私保护学习对家用人形至关重要**
>
> 进入家庭的人形机器人处理的数据包含**家庭成员面孔、居住布局、生活习惯**等高度隐私信息。联邦学习 + 差分隐私是当前最实用的技术组合：仅上传模型梯度更新（而非原始数据），并在梯度上添加可控噪声。LoRA 微调天然适合联邦学习 —— 上传的参数量仅为全量模型的 0.1-1%，通信带宽可控。

> [!CAUTION]
> **现实口径：机器人车队的「联邦学习」多数还停在研究阶段**
>
> 跨本体、跨场景的机器人做 FedAvg 有真实困难：各机器的**本体/传感器/任务分布高度异构**（non-IID 极端），直接平均梯度容易互相拖累；端侧训练算力也有限。2025-2026 量产车队更常见的其实是「**集中式数据湖 + 云端再训练 + OTA 下发模型**」（数据经脱敏/授权后回传），以及「**端侧只存个性化 LoRA 适配器、不动主干**」。把「联邦学习」当成已落地的默认方案是过度承诺——它更多是隐私敏感场景（家庭/医院）的**研究方向与合规叙事**，而非当前主流工程实践。

## 7. 世界模型

### 7.1 什么是世界模型

世界模型（World Model）是从数据中学习的**环境动力学模型**：给定当前状态（或观测）与候选动作，预测未来观测、状态或奖励 —— 相当于机器人脑内的「想象引擎」。它与策略模型互补：策略回答「现在该做什么」，世界模型回答「做了之后会发生什么」。

```mermaid
graph LR
    subgraph 世界模型
        ENC["观测编码器真实帧 → 潜状态"]
        DYN["动力学模型潜状态 + 动作 → 下一潜状态"]
        DEC["解码/预测头潜状态 → 预测未来帧/奖励"]
    end

    OBS["当前观测"] --> ENC --> DYN
    ACT["候选动作序列"] --> DYN
    DYN --> DEC --> PRED["想象的未来轨迹"]
    PRED -->|"评估候选动作"| PLAN["基于模型的规划MPC / 树搜索"]
    PLAN -->|"最优动作"| ROBOT["机器人执行"]
```

### 7.2 三条技术路线与代表工作

| 路线 | 代表工作 | 形态 | 用途 | 端侧相关性 |
| :--- | :--- | :--- | :--- | :--- |
| **视频生成式** | UniSim、Genie / Genie 2 / **Genie 3（2025，实时可交互、分钟级一致性）**、**NVIDIA Cosmos（2025 起的世界基础模型平台，含 Predict / Transfer / Reason 子模型）** | 大规模视频扩散/自回归模型，生成可交互的逼真未来帧 | 合成训练数据、策略预训练环境、神经仿真评估 | 云端为主，推理成本远超端侧预算 |
| **驾驶/具身场景式** | GAIA-1 (Wayve)、**GAIA-2 (2025，多视角可控)**、DriveDreamer、Vista | 领域视频世界模型，条件于动作/布局生成驾驶场景 | 长尾场景生成、闭环仿真评估 | 云端为主 |
| **潜空间/表征预测式** | Dreamer 系列 (DreamerV3)、TD-MPC2、IRIS、**V-JEPA 2 / V-JEPA 2-AC（Meta，2025）** | 紧凑潜空间模型 + 想象 rollout + 规划/策略学习；V-JEPA 2 在**表征空间**（而非像素）预测，动作条件版 V-JEPA 2-AC 可直接做机器人规划 | 样本高效 RL、基于模型的规划（在潜空间评估候选动作序列） | **端侧最相关**：模型小（MLP/CNN 级），TD-MPC2 类可在嵌入式平台做短时程 MPC；表征空间预测避开像素生成的高成本 |

> [!NOTE]
> **2025 的关键分野：生成像素 vs 预测表征**
>
> 视频生成式（Cosmos / Genie 3 / GAIA-2）追求「画出逼真的未来帧」，代价是算力极大、且画面逼真≠物理正确。**V-JEPA 2（2025）** 代表另一条路：**不生成像素，只在表征空间预测未来**，再用动作条件版（V-JEPA 2-AC）做规划——据报道用数十小时机器人数据即可实现零样本抓取放置（**具体数字需核实**）。对端侧而言，「预测表征」比「生成视频」现实得多：它把世界模型从「云端数据引擎」拉回到「机载规划器」的可行区间，是 §7.3 诚实边界里唯一已有真机证据的方向。

### 7.3 世界模型驱动的规划与训练

三种落地用法：

1. **基于模型的规划（Model-Based Planning）**：在潜空间对多条候选动作序列做想象 rollout，用预测奖励选最优（TD-MPC2 的 MPPI 式采样、Dreamer 的想象训练、V-JEPA 2-AC 的表征空间规划）。相比无模型 RL，样本效率高一到两个数量级（公开论文口径）。
2. **数据与训练引擎**：Genie 类可交互环境让策略在「生成的世界」里预训练；Cosmos / GAIA-2 类模型批量生成长尾场景与合成轨迹，喂给下游 VLA（GR00T 的「数据金字塔」中层即来自此类合成数据）。
3. **部署前评测（神经仿真回归测试）**：策略先在 UniSim / Cosmos / 1X World Model 类神经仿真器里 rollout，暴露明显失败再上真机，降低试错成本与安全风险。这是 2025 人形厂商较看重的用法——但前提是世界模型本身足够可信（见下）。

> [!CAUTION]
> **诚实边界**
>
> - **视频生成式世界模型远未达到实时闭环控制**（生成一帧的成本以秒计），「用世界模型直接驱动端侧机器人」仍处早期研究阶段。端侧可落地的形态是：轻量潜空间/表征动力学模型做短时程规划（100ms-1s 视野），长时程预测与数据生成留在云端。
> - **物理一致性是未解难题**：画面逼真 ≠ 物理正确——生成视频可能违背守恒律、穿模、物体恒常性失败；而 FID/FVD 这类视频质量指标**衡量不了物理正确性**，缺乏可靠评测正是「用世界模型做评测」自身的软肋。
> - **唯一已有真机证据的方向是表征空间预测**：V-JEPA 2-AC（2025）证明「不生成像素、只预测表征」的世界模型能驱动真实机器人做零样本操作，这比视频生成式路线更接近端侧可用。
>
> 面试或方案设计中，把世界模型说成「端侧已可用的规划器」是过度承诺；稳妥表述是「云端做数据引擎与离线评测，端侧做短时程表征预测规划」。
